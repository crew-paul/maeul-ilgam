# 화면·디자인 기준

## 제품의 성격

실제 지역 일감을 작성하고 찾아보는 실무 서비스. 차분하고 읽기 쉬우며 구체적이다. 농가의 작업 내용과 참여자가 판단할 조건이 화면의 중심이다. 과장된 슬로건, 장식용 풍경·AI 마스코트, 의미 없는 수치와 작동하지 않는 탐색 요소를 넣지 않는다.

## 화면 계열

- 공개 화면: 지역과 실제 모집 일감이 먼저 보인다. 첫 화면에 검색/지역 선택과 실제 목록을 제공한다. 도메인 소개는 짧게 배치한다.
- 농가 작업함: 초안·검토 요청·모집 중·응답 필요·진행 중을 행동 중심으로 구분한다. 승인 전후의 상태를 동일한 카드 색만으로 표현하지 않는다.
- 작성 화면: 입력/녹음, 원문 수정, 조건 질문, 구조화 폼, 공개 미리보기 순이다. 긴 폼은 단계로 나눠도 서버 초안은 하나다.
- 참여자 화면: 직무·장소·일정·보수·지급일·교통·남은 자리·농가 확인을 비교할 수 있다. 개인별 점수를 만들지 않는다.
- 작업 상세: 양측이 확인한 조건 버전, 다음 행동, 대화, 완료/지급 상태와 이력을 볼 수 있다.
- 운영 화면: 처리할 큐와 사유가 우선이다. 검토와 임의 대리 행위를 구별한다.

## 시각 체계

기존 IBM Plex Sans와 한국어 시스템 글꼴을 기반으로 검증한다. 본문 16px 전후와 충분한 줄 간격, 제한된 글자 크기와 400/500/600 굵기를 사용한다. 중립 배경·세 가지 텍스트 역할·초록 강조 한 계열, 의미 있는 경고/오류만 별도 상태색을 둔다. 여백은 4px 배수, 입력·버튼·카드 규칙은 공통 토큰으로 관리한다.

과거 Framed sheet 구도는 제품 브랜드 자체가 아니다. 화면별 실제 업무에 맞게 공개 목록, 작업함, 작성, 대화 레이아웃을 설계한다. 기능과 정보 구조를 한 화면 구성에 억지로 맞추지 않는다.

## 반드시 그릴 상태

각 화면의 로딩·빈 데이터·부분 실패·권한 없음·만료 세션·정지·삭제/마감·오래된 데이터·저장 충돌·좁은 화면을 설계한다. 마이크 거부·녹음 중단·전사 실패·AI 미설정·모델 제한도 포함한다. 사용자 입력은 오류 후 보존한다.

## 디자인 검증

대표 데스크톱과 390px 모바일에서 실제 데이터 길이로 확인한다. 영문과 한글, 긴 지역명·제목, 시간/보수 단위, 다중 상태에서 잘림·가로 넘침을 확인한다. 키보드와 스크린리더 이름, 대비와 확대를 검사한다. taste-skill/unslop 검사는 보조 도구이며 업무 흐름 인수 기준을 대체하지 않는다.
