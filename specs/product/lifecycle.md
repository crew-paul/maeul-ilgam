# 상태 전이와 직접 지급

## 일감 상태

`draft → pending_review → published → closed → archived`

`pending_review → changes_requested → draft`로 보완한다. 공개 전 운영자는 `rejected`로 처리할 수 있고 사유를 남긴다. 게시물은 운영자에 의해 `suspended`될 수 있다. 정지는 탐색·신규 신청을 막으며 기존 참여 기록은 보존한다.

- 게시 조건: 확인된 농가, 필수 조건 완성, 정책 동의, 과거 시각이 아닌 모집·작업 일정, 허용 업무.
- 모집 마감·인원 충족·농가 수동 마감 시 `closed`. 작업 상태는 별도 engagement에서 추적한다.
- 확정 전 삭제는 비공개 처리다. 신청이나 확정 기록이 있는 일감의 물리 삭제는 금지한다.
- 게시 후 보수·일정·업무·장소·인원 변경은 새 revision을 만든다. 신청자는 변경 알림을 받고, 이미 확정된 조건은 자동으로 바뀌지 않는다.

## 신청 상태

`submitted → offered → accepted` / `submitted → declined` / `submitted|offered → withdrawn`

- 로그인한 참여자가 공개 모집 중인 일감에 신청한다. 본인 농가 일감 신청은 금지한다.
- `(job_id, applicant_id)`는 중복 신청을 막는다. 철회 후 재신청은 새 시도 이력을 남기고 활성 신청은 하나만 유지한다.
- 제안은 당시 job revision, 유효기간과 모집 자리 예약을 가진다. 만료 시 `expired`로 남고 자리를 돌려준다.
- 참여자 수락은 트랜잭션에서 모집 잔여 인원·상태·유효기간을 재검사한다. 동시 수락으로 정원이 초과되지 않는다.
- 자동 선발·AI 지원자 순위는 없다. 농가의 제안과 참여자의 수락이 모두 있어야 engagement가 생긴다.

## 확정 작업

`confirmed → in_progress → completion_requested → completed`

`confirmed|in_progress|completion_requested → cancellation_requested → cancelled` 또는 기존 상태 복귀. 한쪽의 취소 요청만으로 완료·지급 기록을 삭제하지 않는다. 운영자는 안전·신고 대응을 위해 작업 진행을 `on_hold`로 표시할 수 있고 사유와 전 상태를 보존한다.

조건 변경은 별도 `change_request`다. 제안한 조건은 양측이 수락한 뒤 새 합의 버전이 된다. 일방적으로 원래 조건을 덮어쓰지 않는다. 늦은 응답·거절·철회·취소·운영 중단은 모두 기록한다.

## 직접 지급 기록

작업 상태와 지급 상태를 분리한다.

`not_reported → payer_reported → recipient_confirmed`

어느 단계든 이견이 제기되면 `disputed`; 운영자는 사실 확인 기록을 남기고 `resolved`로 표시할 수 있으나 실제 송금 여부를 임의로 확정하지 않는다.

- 확정 시 금액·통화·단위·계산 기준·예상 시간·지급 예정일·직접 지급 방식을 스냅샷으로 저장한다.
- 일급/시급이면 실제 작업 시간을 양측이 확인하고 합계 산출 근거를 남긴다. AI가 임의 계산하거나 금액을 결정하지 않는다.
- 농가의 ‘지급했다고 기록’과 참여자의 ‘수령 확인’을 명확히 구분한다. 영수증 등 증빙은 선택이며 공개하지 않는다.
- 미지급·이견 신고와 운영 지원은 가능하나 플랫폼의 금전 보증이나 법적 판정으로 표현하지 않는다.

## 메시지와 알림

일감 문의는 로그인 후 농가와 질문자만 본다. 제3자의 대화에 접근할 수 없다. 확정 후 양측이 필요한 집결 정보를 대화로 공유한다. 주요 상태 변경은 DB에 기록한 뒤 outbox에서 이메일과 서비스 내 알림으로 발송한다. 중복 재시도는 중복 알림을 만들지 않는다.
