# Design system and acceptance criteria

- Use a restrained green for primary actions, dark text on white, and neutral rules for grouping; do not rely on color alone for state.
- Keep body and form text readable, primary controls at least 56px high, and clear keyboard focus indicators. Use system fonts including Korean fallbacks.
- Give the job list priority over promotional content. Every listing exposes location, task, date and pay, with a visible detail action.
- Registration starts with text. Keep every field visible, group related fields with headings, and keep voice input optional. Preserve validation, review, and existing routes and API behavior.
- At narrow widths, stack the registration grid, keep navigation available and search usable without horizontal overflow.
- Confirm both English and Korean, desktop and mobile, and the farmer and applicant journeys in a real browser when available. The local build and API journey tests do not substitute for visual inspection.
