# 출시 인수 기준

## 필수 시나리오

| ID | 검증할 결과 |
|---|---|
| A01 | 농가와 참여자가 별도 브라우저/계정으로 로그인하고, 새로고침·재로그인 후 서버에 저장된 데이터를 복구한다 |
| A02 | 미확인 농가는 초안을 저장할 수 있으나 게시할 수 없고, 확인 담당자만 사유와 함께 처리한다 |
| A03 | 영어·한국어 입력과 음성 전사문을 수정해 초안을 생성한다. 없는 보수·날짜는 채워지지 않고 게시가 차단된다 |
| A04 | 수동 확정 필드와 AI 수정이 충돌하면 사용자 확인을 요구한다. AI 장애 중 수동 게시 작성은 가능하다 |
| A05 | 공개된 일감만 목록/필터/상세에 나타나고 마감·정지·정원 상태가 일치한다 |
| A06 | 다른 계정의 일감·신청·대화·증빙 ID로 접근/수정 시 차단된다. 운영자 권한도 서버에서 검사한다 |
| A07 | 중복 신청·중복 클릭·네트워크 재전송이 한 번만 처리되고 철회·거절·만료가 기록된다 |
| A08 | 정원이 하나 남았을 때 동시 제안 수락으로 인원이 초과되지 않는다 |
| A09 | 게시 조건을 바꿔도 확정된 작업 조건은 바뀌지 않는다. 양측 변경 동의 후에만 적용된다 |
| A10 | 대화·알림은 정해진 당사자에게만 도달하고 이메일 재시도로 중복 발송되지 않는다 |
| A11 | 작업 완료·지급 신고·수령 확인이 분리된다. 한쪽만 보고하면 양측 확인 완료로 표시되지 않는다 |
| A12 | 취소·이견·신고·정지를 처리하고 관련 당사자에게 알린다. 과거 조건·기록은 보존된다 |
| A13 | 모바일 390px, 데스크톱, 키보드, 화면 확대와 영어/한국어에서 등록·탐색·신청·완료 전체가 가능하다 |
| A14 | 만료 세션·오류·빈 목록·오프라인·오래된 버전 충돌에서 데이터가 조용히 사라지지 않는다 |
| A15 | 운영 키 비노출, 토큰 일회성·요청 제한·업로드 검증·CSRF·개인정보 비공개 검사를 통과한다 |
| A16 | 스테이징 배포·스키마 이행·실제 이메일·비공개 업로드·백업 복구·롤백을 확인한다 |

## 출시 게이트

- G1 기능: P01–P10 인수 기준과 A01–A16 통과. 검증 기록에 환경·날짜·결과·관련 커밋을 남긴다.
- G2 운영: 첫 지역과 운영 주체, 지원 채널, 농가 확인 담당, 모집·보수·개인정보 정책과 보관 기간 확정.
- G3 실사용 준비: 동의받은 농가와 참여자로 한 건 이상 전체 여정의 사용성 점검. 문제를 기록하고 출시 차단 문제 해결.
- G4 공개: HTTPS 도메인, 키·오류·알림 모니터링, 실제 복구 연습, 관리자 계정, 롤백 담당 확인.

기능 검증은 직접 관련된 단위/통합/계약 테스트를 사용하고, 최종 출시 게이트에서 전체 핵심 E2E와 보안 경계 검사를 수행한다. 통과하지 못한 항목은 미완료로 남긴다.

## 해커톤 제출 게이트

공개 코드 저장소, 접근 가능한 3분 데모 링크, 실제 배포 링크 또는 실행 방법, 실제 사용한 Meta 모델 설명, 기간 중 신규 기여 명시를 준비한다. 제출 설명·영상·코드의 기능 범위가 일치해야 한다. 재현 이미지와 가상 계정은 표시하고, 실제 구인·작업·지급 결과를 꾸미지 않는다.
