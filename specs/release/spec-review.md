# v2 정리 결과와 남은 결정

## 수정한 명세 문제

| 이전 문제 | v2 수정 |
|---|---|
| 사용자끼리 연결되는 제품인데 같은 세션 화면 전환을 완료로 정의 | 독립 계정·데이터·게시·탐색·신청·수락·작업을 성공 여정으로 정의 |
| DB와 계정을 출시에서 제외 | 영구 데이터·인증·소유권·백업을 필수 요구사항으로 지정 |
| 승인과 실제 게시를 혼용 | draft·검토·published와 engagement를 별도 상태로 정의 |
| 목록·상세·문의·운영 기능 누락 | 화면 경로, 데이터 단위, API와 역할별 권한에 포함 |
| 직접 지급의 확인·이견 처리 없음 | 지급 조건 스냅샷과 양측 보고, 신고·검토 절차 정의 |
| 디자인·영상 작업을 제품 완성 근거로 사용 | 출시 게이트와 해커톤 제출 게이트를 구별 |
| 오래된 검증·새 요구사항이 충돌 | 이전 기록 표시와 현재 구현 차이 표, 새 활성 작업을 분리 |

## 출시 전 결정이 필요한 사항

- 첫 운영 시·군과 실제 운영 주체·농가 확인 담당자·지원 연락처
- 호스팅·DB·객체 저장소·이메일 공급자와 운영 계정
- 실제 모집 가능한 업무 목록과 운영/이용/개인정보 정책 및 데이터별 보관 기간
- 직접 지급 방식의 허용 범위, 이견 접수와 처리 책임·응답 시간

직접 지급 자체는 사용자 확정 사항이다. 위 결정은 구현을 시작하기 위한 허락 요청이 아니라 실제 이용자를 받기 전 필요한 운영 정보다. 아직 확인되지 않은 값은 문서나 화면에 실제 서비스 정보처럼 넣지 않는다.

## 문서 검증 범위

이번 작업은 명세 수정이다. 로컬 Markdown 링크, 활성 작업의 plan/requirements/validation 존재 여부, 요구사항·상태·완료 기준의 일치 여부를 확인한다. 앱 테스트나 API 호출은 이번 문서 변경 검증에 필요하지 않으며 실행하지 않는다. 구현 검증은 각 후속 작업에서 수행한다.

검증 결과(2026-11-02): specs 아래 로컬 Markdown 링크 검사 통과. 활성 서비스 작업 9개 모두 plan·requirements·validation 파일 존재 확인. 기존 시제품 요구사항에는 v2 기준으로 이관됐다는 표시를 추가했고, 앱 코드·비밀 설정은 변경하지 않았다.
